## 1. Purpose

This addendum records design limitations discovered during the analysis of
the pilot stage (200 runs, completed 2026-11-28). It does **not** modify
H1–H6, does not modify falsification criteria, and does not modify the
pilot results. It records that the original design **cannot test** three
of its six hypotheses, and therefore that the confirmatory stage **will
not be run** under the original design.

A revised experimental cycle, Phase II-bis, will be designed separately
with its own preregistration.

### 2.2 Design limitations

**Limitation A — `R4_control` fires on `cycle` alone.**
`model/rules.py:178-187` defines `R4_control` as
`view.cycle >= CONTROL["R4_control_threshold"]`, with no reference to
`constraint_conflict`. The treatment rule `R4_constraint_conflict`
depends on a state predicate, not on cycle count. The two rules are not
"structurally equivalent" in the sense required by the definition of H1.
In S1_control, `R4_control` fires on 16 consecutive cycles even though no
shared resource exists and no constraint conflict occurs.

**Limitation B — `safety_violations` cannot increase in any scenario.**
`model/msm.py:57` increments `safety_violations` only when
`state.pending_local_action_would_violate` is `True`. In
`model/engine.py:_apply_fault`, `pending_local_action_would_violate` is
set to `False` in every fault path. No code path sets it to `True`.
Therefore `safety_violations = 0` in every run of every scenario,
regardless of condition. H1 and H4 cannot be tested against a variable
that is structurally constant.

**Limitation C — `secondary_damage` is computed before any escalation.**
`model/engine.py:73-85` computes `secondary_damage` inside
`_apply_fault`, which runs before `_choose_decision` in the same cycle.
With `repeat: 0` in `S2.yaml`, `_apply_fault` runs exactly once (cycle 2).
No mechanism exists by which an escalation decision could reduce
`secondary_damage`: the damage is already fixed before the decision is
made. H2 cannot be tested.

**Limitation D — `S2.yaml` describes a causal path the code does not
implement.**
`S2.yaml` states: "if escalation is early enough, secondary damage to
other components sharing the resource is reduced." As shown in C, the
code does not implement this path. The scenario's description and its
`can_fail_how` entries (FM-1, FM-2, FM-3) refer to dynamics the model
does not contain.

## 3. Consequences for hypothesis testing

| Hypothesis | Status after this addendum | Reason |
|---|---|---|
| H1 | **UNTESTED** | `safety_violations` is structurally zero (Limitation B) |
| H2 | **UNTESTED** | No causal path from escalation to secondary damage (Limitation C) |
| H3 | **TESTABLE only if consistency varies** | Pilot shows consistency = 20/20 in all cells; no evidence yet that it can vary under the current design |
| H4 | **UNTESTED** | Same as H1 (Limitation B) |
| H5 | **PENDING** | TLC not available |
| H6 | **VERIFIED in pilot** | RNG is consumed in S2 (secondary_damage distinct = {0,1,2,3}); determinism holds per seed |

**H1, H2, and H4 are not falsified.** They are untested. The distinction
is recorded here so that no future reader interprets the pilot output as
evidence against these hypotheses.

## 5. What happens next

1. **Confirmatory stage of Phase II will not be run.** Running it would
   produce 800 runs in which H1, H2, and H4 are structurally constant,
   and would constitute a falsification-by-design, which is prohibited by
   `PREREGISTRATION.md` §5.3 and by the project's governing principles.

2. **Phase II is closed as an original experimental design**, with this
   addendum documenting its limitations.

3. **Phase II-bis will be designed separately**, with:
   - a new preregistration (`PREREGISTRATION_BIS.md`);
   - new, disjoint seed sets (`seeds_pilot_bis.txt`,
     `seeds_confirmatory_bis.txt`);
   - a revised implementation that addresses Limitations A, B, C, and D;
   - its own pilot, then its own confirmatory;
   - results published under the name Phase II-bis, not Phase II.

4. **The Phase II pilot results are preserved** as a diagnostic record.
   They document what the model does, not what the hypotheses claim.

## 6. Methodological note

> An experiment that cannot produce the outcome required to falsify its
> hypothesis cannot be rescued by statistical analysis or post-hoc
> calibration.

> A hypothesis that a design cannot falsify is not a falsified hypothesis;
> it is an untested one, and must be recorded as such.

The value of this addendum is that it prevents a falsification that would
have been attributable to the design from being reported as a
falsification of the phenomenon.

## 7. Note on an earlier internal assessment

During the analysis leading to this addendum, an internal assessment
suggested that H1 might be testable in S1, S3, S4, and S5 after fixing
Limitation A. On re-examination, this was incorrect: the outcome
variable `safety_violations` is structurally constant (Limitation B), so
fixing Limitation A alone would not make H1 testable in any scenario.
This note is recorded to keep the diagnostic trail complete.
